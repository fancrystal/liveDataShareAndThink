# 小红书内容分析与生成开源项目调研

调研日期：2026-07-09

## 1. 调研结论

目前没有一个成熟开源项目能够完整提供：

> 小红书数据获取 → 热点与爆款分析 → 账号策略 → 原创内容生成 → 审核发布 → 效果复盘

现有项目主要集中在四类：

1. 小红书公开笔记、评论和账号数据访问；
2. 浏览器自动化发布与互动；
3. 基于大模型的内容生成工作流；
4. 直播流录制和视频下载。

第一期应采用组合式架构，但不能把这些项目直接拼接成产品。数据模型、分析指标、内容生成流程、证据链和知识库需要自行设计。

## 2. 推荐等级说明

- **A：优先评估**——能力契合、许可相对清楚，可进行隔离验证。
- **B：局部复用**——适合作为独立工具或边缘能力，需要控制耦合。
- **C：研究参考**——许可、维护状态或产品边界不适合成为核心依赖。
- **D：第二期候选**——主要用于直播复盘，第一期不集成。

Star 数量仅为调研当日快照，只用于衡量社区关注度，不代表代码质量或合规性。

## 3. 第一优先级项目

### 3.1 lucasygu/redbook

- 地址：<https://github.com/lucasygu/redbook>
- 调研快照：约 376 Stars，MIT License，Node.js/TypeScript。
- 推荐等级：**A**
- 定位：面向 AI Agent 的小红书 CLI。

主要能力：

- 关键词、话题、推荐流和用户搜索；
- 笔记正文、评论、用户资料和账号内容读取；
- 关键词矩阵、跨话题热力图、互动信号分析；
- 头部博主、内容形式、受众和内容机会分析；
- 单篇爆款拆解和多篇爆款模板抽取；
- 数据驱动选题；
- Markdown 转小红书风格图片卡片；
- 评论管理、笔记健康检查和图文发布。

适合本项目的部分：

- 作为公开内容数据适配器的首选验证对象；
- 借鉴其结构化输出和分析模块划分；
- 验证关键词研究、账号对比、评论读取和笔记读取链路；
- 在早期原型中使用 CLI 进程边界隔离平台变化。

风险与注意事项：

- 项目较新，需要通过真实账号做稳定性验证；
- 依赖浏览器 Cookie 和非官方接口签名，平台更新可能导致失效；
- 项目文档说明发布步骤容易触发验证码；
- 不应把其输出直接等同于完整市场样本；
- 最终应通过本项目的数据适配器接口调用，避免核心业务依赖其内部结构。

### 3.2 jackwener/xiaohongshu-cli

- 地址：<https://github.com/jackwener/xiaohongshu-cli>
- 调研快照：约 2.3k Stars，Python。
- 推荐等级：**A/B**
- 定位：通过逆向接口提供搜索、读取、互动和发布能力的 CLI。

主要能力：

- 浏览器 Cookie 和二维码登录；
- 笔记、用户、话题搜索；
- 笔记详情、评论、子评论和用户资料；
- 推荐流和分类热门内容；
- 收藏、关注、点赞、评论和回复；
- 图文发布及自己账号的笔记管理；
- YAML/JSON 稳定结构化输出；
- 退避、冷却和请求抖动等保护措施。

适合本项目的部分：

- 作为 `redbook` 的备选数据适配器；
- 参考稳定输出封装和错误信封设计；
- 用于对同一个查询进行交叉验证。

风险与注意事项：

- 同样依赖非官方接口；
- 需要进一步核验许可证后才能确定代码级复用方式；
- 两个 CLI 不应同时成为核心强依赖，建议通过统一接口二选一或互为回退。

### 3.3 xpzouying/xiaohongshu-mcp

- 地址：<https://github.com/xpzouying/xiaohongshu-mcp>
- 调研快照：约 14.6k Stars，97 个 Releases，Go。
- 推荐等级：**B/C**
- 定位：小红书浏览与发布 MCP 服务。

主要能力：

- 登录状态管理；
- 发布图文和视频；
- 定时发布；
- 首页推荐、关键词搜索；
- 笔记详情、评论和用户主页；
- 点赞、收藏、评论和回复；
- HTTP/MCP 接口和 Docker 部署。

适合本项目的部分：

- 验证发布、登录和浏览器自动化流程；
- 参考平台操作适配器的接口设计；
- 作为开发环境中的外部服务进行概念验证。

风险与注意事项：

- 仓库未声明开源许可证，不能默认获得复制、修改和商业分发权；
- 不建议把源码复制进本项目；
- 自动操作存在验证码、Cookie 失效和账号风控风险；
- 第一阶段只考虑“人工确认后发布”，不能默认自动批量操作；
- 若未来要作为正式依赖，应先获得作者授权或采用许可清晰的替代实现。

## 4. 数据采集与素材归档

### 4.1 NanmiCoder/MediaCrawler

- 地址：<https://github.com/NanmiCoder/MediaCrawler>
- 调研快照：约 55.9k Stars，Python。
- 许可证：Non-Commercial Learning License 1.1。
- 推荐等级：**C**

主要能力：

- 小红书关键词搜索；
- 指定笔记和创作者主页采集；
- 一级、二级评论；
- CSV、JSON、Excel和数据库存储；
- 登录态、代理和评论词云；
- 同时支持多个主流内容平台。

价值：

- 项目结构、浏览器登录态、存储抽象和采集任务设计值得研究；
- 适合内部学习和非商业原型验证。

限制：

- 许可证明确禁止商业用途和大规模采集；
- 不能作为未来商业产品的核心依赖；
- 开源版重点是采集，深度内容拆解在其商业版本中；
- 本项目应自行实现合规、限频的数据适配层。

### 4.2 JoeanAmier/XHS-Downloader

- 地址：<https://github.com/JoeanAmier/XHS-Downloader>
- 调研快照：约 11.9k Stars，GPL-3.0，Python。
- 推荐等级：**B**

主要能力：

- 提取账号发布、收藏、点赞和专辑作品；
- 提取搜索结果中的作品与用户；
- 获取作品信息和下载地址；
- 下载图文、视频和 Live Photo；
- API、MCP、Docker和断点续传。

适合本项目的部分：

- 用户明确授权后的参考素材归档；
- 视频内容转录前的资源获取；
- 对标内容截图和素材证据留存。

风险与注意事项：

- GPL-3.0 会带来分发和衍生作品开源义务；
- 未接受相应义务前，不把其代码复制进平台；
- 素材下载不代表获得内容版权；
- 更适合以独立进程使用，或仅研究协议后自行实现最小能力。

### 4.3 linxule/opencli

- 地址：<https://github.com/linxule/opencli>
- 推荐等级：**B/C**
- 定位：将网站能力统一包装成适合 Agent 使用的 CLI。

小红书相关能力包括：

- 搜索、笔记、评论、推荐流和用户；
- 下载、发布和通知；
- 创作者笔记、笔记汇总、详情、账号资料和统计。

价值：

- 适合参考多站点适配器和 Agent 工具协议；
- 可能提供创作者后台数据访问的验证路径。

风险：

- 项目范围很大，小红书只是众多适配器之一；
- 正式采用前需要单独检查小红书适配器的成熟度、许可证和测试情况。

## 10. 不建议的做法

- 直接 Fork `MediaCrawler` 作为商业平台主体；
- 把未声明许可证的项目源码复制进仓库；
- 用绝对点赞数定义“爆款”，忽略发布时间、粉丝基数和赛道差异；
- 抓取少量搜索结果后宣称代表整个平台趋势；
- 自动生成后不经审核直接批量发布；
- 把分析内容结构变成逐字仿写；
- 把 Cookie、账号登录态和模型密钥存入业务数据库明文；
- 把平台适配逻辑散落在分析和生成代码中。

## 11. 对本项目的最终建议

本项目应拥有自己的核心：

1. 统一领域模型：研究项目、关键词、笔记、作者、评论、指标快照、洞察、选题、草稿、审核和发布结果。
2. 数据证据链：每条洞察都能回到原始样本和计算方法。
3. 相对表现模型：结合发布时间、粉丝基数、赛道基线和互动质量识别高表现内容。
4. 原创生成工作流：从需求与结构模式生成新内容，而不是重写单篇原文。
5. 账号知识库：沉淀有效选题、失败实验、语气、禁忌和历史效果。
6. 可替换平台适配器：任何非官方项目失效时，核心分析与产品仍能继续工作。

开源项目的价值是缩短平台接入和原型验证时间，而不是替代这个核心。
