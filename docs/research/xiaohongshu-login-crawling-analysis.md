# 小红书开源项目：登录、采集与分析实现梳理

调研更新：2026-07-10

## 共同模式

这些项目绝大多数不是无登录的传统 HTTP 爬虫。共同链路是：

> 用户在本机浏览器完成小红书登录 → 工具读取或创建本地登录态 → 用浏览器自动化或非官方 Web 接口读取页面数据 → 转换为结构化 JSON/CSV → 用规则或 LLM 生成分析结论

因此，登录态、浏览器指纹、验证码、会话过期和平台页面变化都是外部适配器要处理的风险；它们不应进入本项目的业务数据库或核心分析模块。

## 各项目的登录与采集方式

| 项目 | 登录方式 | 数据获取方式 | 分析方式 | 对本项目的启示 |
|---|---|---|---|---|
| `lucasygu/redbook` | 自动读取 Chrome 已登录 Cookie；Windows Chrome 127+ 会使用 headless Chrome 读取 App-Bound Encryption Cookie；失败时可手工传 Cookie | CLI 调用搜索、笔记、评论、账号等非官方能力，并提供 JSON 输出 | 对关键词、博主、互动比例、标题钩子、评论主题和内容模板做组合分析 | 作为一期“只读、按关键词采集”的首选外部进程；本项目只消费其 JSON，不复制其登录逻辑 |
| `jackwener/xiaohongshu-cli` | 优先读取本地缓存 Cookie，自动从多种浏览器提取；支持二维码登录；Cookie 默认 7 天后刷新 | 逆向 Web API，包含签名、限频、指数退避、会话稳定指纹与验证码冷却 | 提供结构化信封和搜索/笔记/评论/热门流等原始数据；分析适合由本项目完成 | 作为 `redbook` 的回退与交叉验证来源；其“错误类型 + 稳定输出”设计值得借鉴 |
| `jackwener/xhs-cli` | 读取本地 Cookie 或二维码登录，并校验是否为有效非访客会话 | 用 camoufox 打开真实页面，从 `window.__INITIAL_STATE__` 提取结构化数据；互动操作使用真实 DOM | 以原始页面状态为主，不强调指标模型 | 更接近“浏览器采集器”；优点是页面路径直观，代价是浏览器依赖重、页面改动敏感 |
| `xpzouying/xiaohongshu-mcp` | 独立登录工具和二维码；Cookie 挂载在本地/Docker 数据目录 | Chromium/CloakBrowser 自动化，经 MCP 暴露搜索、详情、评论和发布工具 | 主要由 AI Agent 根据工具返回内容生成结论 | 适合人工操作或 Agent 试验；不作为一期核心依赖，也不自动化发布 |
| `aki66938/xhs-toolkit` | Cookie 获取、验证与管理 | Playwright 操作创作者中心，定时采集仪表盘、内容和粉丝数据，导出 CSV | 对中文表头的本地数据做 AI 趋势/最佳笔记分析 | 对“自有账号数据回收 + 定时任务 + 本地导出”有参考价值，但不解决站内竞品搜索 |
| `MediaCrawler` | 浏览器登录态、代理等 | 多平台关键词、笔记、作者及评论采集并写入文件/数据库 | 评论词云等基础处理 | 仅研究其任务、存储和限频抽象；许可证不适合本项目商业核心依赖 |

## 分析能力的真实情况

多数所谓“AI 分析”分两层：第一层是采集到标题、正文、互动量、发布时间、作者信息和评论；第二层是由规则或大模型把这些字段总结为“爆款标题结构、互动率、评论痛点、内容模板和选题建议”。真正可靠的部分是可追溯的原始数据和计算公式；LLM 负责归纳与写作，不应凭空判断趋势。

`redbook` 的方向最贴合一期：关键词研究、竞品比较、爆款拆解、评论主题归纳和内容机会建议。我们仍需自行实现“相对表现评分 + 证据链 + 原创草稿审核”，防止分析不可复核或变成逐字仿写。

## 本项目的最小实现

第一期只做只读的关键词样本采集：用户自行在本机 Chrome 登录，后端通过独立 `redbook` 进程取得结构化结果，标准化后写入笔记、作者和指标快照。错误分为“未安装命令”“未登录或 Cookie 过期”“验证码/风控”“平台输出不兼容”，并保留固定样本导入作为可重复测试路径。

不做：绕过验证、批量互动、自动发布、代理池、Cookie 上传或把 Cookie 写入数据库。站内数据仅用于小样本洞察，应在界面中保留采集时间、关键词、来源和局限说明。
