# 小红书内容引流平台第一期设计

状态：已确认，待实施计划  
确认日期：2026-07-09

## 1. 背景

LiveDataShareAndThink 将建设一个面向内容运营与直播增长的智能分析和内容生产平台。

项目分两期推进：

- 第一期只做小红书内容引流；
- 第二期再做直播录像、话术和经营效果复盘。

第一期通过小红书公开内容、自有账号数据和用户提供的业务资料，发现热点与内容机会、拆解高表现内容、生成原创引流内容，并沉淀可持续复用的账号知识。

## 2. 目标

第一期必须形成以下闭环：

1. 用户创建研究项目并填写账号定位、目标人群、关键词和竞品账号。
2. 系统获取或导入相关小红书笔记、作者、评论和互动指标。
3. 系统生成可解释的热点、竞品、内容结构和用户需求分析。
4. 用户从分析结果生成带证据的选题。
5. 系统生成用于直播预热、直播预约或直播后承接的原创内容。
6. 用户审核、编辑、保留版本并导出内容。
7. 后续可导入发布表现，形成账号自己的内容经验库。

首个可运行版本必须打通：

> 输入关键词 → 获取或载入样本 → 保存数据 → 展示高表现内容 → 生成一篇带依据的草稿

## 3. 非目标

第一期不包含：

- 抖音、快手等其他平台；
- 直播录像、语音转写和直播话术复盘；
- 注册、登录、计费、多租户和复杂权限；
- 第三方账号的非公开成交额、订单或用户隐私数据；
- 规避验证码、风控或平台限制的对抗功能；
- 无人审核批量发布；
- 未授权素材搬运、逐句洗稿或自动仿写；
- 将某个非官方爬虫仓库直接改造成项目主体。

## 4. 用户与部署方式

第一期服务单用户或单个内部团队，采用私有部署。

系统不建设用户账户体系，但允许用户创建多个研究项目和多个账号定位。项目之间在业务数据上独立，使用同一套本地系统配置。

系统以 Docker Compose 作为标准部署形态，同时保留本地开发启动方式。

## 5. 技术方案

采用 Python 模块化单体：

- 前端：React + TypeScript；
- 后端：FastAPI；
- 数据库：PostgreSQL；
- 后台任务：Redis + Python Worker；
- 数据访问：SQLAlchemy + Alembic；
- 小红书接入：独立平台适配器，首选验证 `redbook` CLI；
- AI能力：OpenAI兼容接口，保留其他模型供应商适配入口；
- 部署：Docker Compose。

Python 是核心技术栈，因为后续分析、文本处理和第二期音视频处理均可复用其生态。Node.js 小红书工具通过独立进程或容器调用，不进入核心业务代码。

## 6. 总体架构

```text
React Web
    │
    ▼
FastAPI
    ├── Project Module
    ├── Collection Module
    ├── Analysis Module
    ├── Ideation Module
    ├── Generation Module
    ├── Review Module
    └── Knowledge Module
          │
          ├── PostgreSQL
          ├── Redis / Worker
          ├── Xiaohongshu Adapter
          └── LLM Adapter
```

模块之间通过应用服务和明确的数据对象通信。平台适配逻辑不得进入分析、选题或生成模块；模型供应商逻辑不得进入领域规则。

## 7. 核心模块

### 7.1 项目模块

职责：

- 管理研究项目；
- 管理账号定位、目标人群、内容语气和禁用表达；
- 管理关键词和竞品账号；
- 提供其他模块所需的项目上下文。

### 7.2 平台适配器

职责：

- 检查登录状态；
- 按关键词搜索公开笔记；
- 读取笔记详情、作者和评论；
- 将第三方输出转换为稳定的适配器数据结构；
- 返回结构化错误和能力状态。

约束：

- 第一适配器验证 `redbook` CLI；
- 适配器必须可以被固定样本适配器替换；
- 业务层不能依赖 CLI 的命令名、字段名或错误文本；
- Cookie、验证码和限流只由适配器层识别和上报。

### 7.3 采集与标准化模块

职责：

- 创建采集任务；
- 保存第三方原始响应；
- 将作者、笔记、指标和评论转换为统一领域模型；
- 根据平台ID去重；
- 为同一笔记保留多次指标快照；
- 记录来源、采集时间、查询条件和数据完整性。

### 7.4 分析模块

职责：

- 计算相对表现和置信度；
- 识别热点、竞品差异和高表现内容；
- 提取内容主题、结构、钩子、情绪、价值和互动设计；
- 从评论识别问题、异议、共鸣和意向信号；
- 生成带证据的分析结论。

### 7.5 选题模块

职责：

- 将分析结论转为选题简报；
- 标记目标人群、内容目标、内容角度和优先级；
- 关联依据和样本；
- 管理候选、采用、搁置和已生成状态。

### 7.6 生成模块

职责：

- 根据选题、账号定位和证据生成三个差异化版本；
- 支持直播预热、直播预约和直播后承接三种目标；
- 生成标题、正文、标签和封面文案；
- 执行长度、必填字段、禁用表达和结构校验；
- 执行原创相似度检查；
- 保存模型、提示模板、输入上下文和生成结果。

### 7.7 审核模块

职责：

- 创建不可变草稿版本；
- 记录编辑、退回、通过和导出；
- 展示证据、风险提示和校验结果；
- 保留完整修改历史。

第一期不直接发布。通过后的草稿支持复制和结构化导出。

### 7.8 知识模块

职责：

- 沉淀被采用的内容模式；
- 保存失败实验和用户反馈；
- 维护账号语气、禁忌和有效表达；
- 为后续选题和生成提供项目级上下文。

第一期使用结构化数据库和可导出的 Markdown/JSON，不引入独立向量数据库。只有当知识规模和检索效果证明有必要时再增加语义检索。

## 9. 数据与任务流程

### 9.1 采集流程

1. 用户在项目中选择关键词并启动采集。
2. API创建 `CollectionRun`，Worker异步执行。
3. 适配器搜索并读取笔记、作者、指标和指定数量评论。
4. 系统先保存原始响应，再执行标准化和去重。
5. 每次采集都创建新的指标快照。
6. 任务完成后更新数量、状态和错误摘要。

### 9.2 分析流程

1. 用户选择项目、关键词和时间范围。
2. 系统验证样本数量和字段完整性。
3. 规则引擎计算统计指标与相对表现。
4. AI分析器对候选样本执行结构和语义分类。
5. 系统合并确定性指标与AI分类。
6. 每项结论生成 `Insight` 和至少一条 `Evidence`。
7. 样本不足时返回低置信度结论或拒绝生成结论。

### 9.3 生成流程

1. 用户从分析结论创建或选择一个选题。
2. 系统生成包含目标、受众、证据和约束的选题简报。
3. AI一次生成三个角度明显不同的候选版本。
4. 系统执行结构校验、规则检查和原创相似度检查。
5. 通过基本检查的内容进入待审核状态。
6. 用户编辑时创建新版本，不覆盖原版本。
7. 通过后可以复制或导出。

## 10. 相对表现模型

系统不以绝对点赞数直接定义爆款。第一期使用可解释的组合分：

- 互动表现：对点赞、收藏和评论等可用指标进行对数归一化；
- 时间效率：结合发布时间和采集时间评估互动积累效率；
- 作者相对表现：与同一作者的其他样本比较；
- 赛道相对表现：与同关键词和同内容形式样本比较；
- 互动质量：评论中的提问、意向、共鸣和信息需求；
- 数据置信度：根据样本量、字段完整性和时间一致性计算。

总分和每项子分均持久化。权重采用版本化配置，界面展示计算版本、样本范围和置信度。

当作者历史数据不足时，作者相对表现不参与加权，并降低置信度。缺失指标不得以零代替，必须标记为未知。

第一期提取：

- 核心主题；
- 目标人群；
- 用户问题或愿望；
- 标题句式与信息密度；
- 开头钩子；
- 正文结构；
- 情绪和信任建立方式；
- 收藏价值；
- 评论触发方式；
- 视觉形式；
- 直播引流关系。

AI标签必须符合版本化结构定义。自由文本解释不能替代结构化字段。

## 12. 原创与风险控制

- 生成输入以多条洞察和抽象模式为主，不以单篇原文作为改写源；
- 草稿保留引用的样本和分析依据；
- 与样本标题、正文的相似度超过阈值时阻止通过；
- 生成内容不得直接复用原图或受保护素材；
- 品牌禁用表达、平台长度规则和必填字段使用配置管理；
- 风险提示不会被模型输出自动覆盖；
- 第一阶段所有内容必须人工审核。

## 14. 错误处理

后台任务状态：

- `queued`；
- `running`；
- `succeeded`；
- `partially_succeeded`；
- `failed`；
- `cancelled`。

错误分为：

- 认证失效；
- 验证码或需要人工操作；
- 平台限流；
- 平台结构变化；
- 网络或进程错误；
- 数据结构不兼容；
- 模型超时；
- 模型结构化输出错误；
- 业务校验失败。

认证、验证码、限流和临时网络错误标记为可恢复。平台结构变化和数据结构不兼容停止自动重试，避免持续错误请求。

AI结构化输出失败时最多修复两次。仍不符合结构则任务失败，不使用不完整输出，不生成虚假默认值。

采集部分成功时保留已成功数据并报告失败明细。任何失败都不能删除已有数据。

## 15. 安全与隐私

- 模型密钥、Cookie和登录态不得进入Git；
- 敏感配置通过环境变量或本地受限配置文件管理；
- 日志统一脱敏；
- 原始响应中的敏感字段在保存前过滤；
- 默认只监听本机或私有网络；
- 第一阶段不提供公网匿名访问；
- 数据导出由用户主动触发。

## 18. 验收标准

第一期验收时必须满足：

- 可以创建多个研究项目和账号定位；
- 可以使用固定样本完成全流程；
- 在有效登录态下可以按关键词获取真实小红书样本；
- 所有笔记具有来源和采集时间；
- 同一笔记支持多个指标快照；
- 高表现判断展示子分、样本范围和置信度；
- 每条关键洞察至少关联一条证据；
- 可以从选题生成三个差异化草稿；
- 草稿保留模型、提示版本、证据和校验结果；
- 编辑不会覆盖历史版本；
- 内容需要人工审核才能标记通过；
- 可以复制或导出通过的内容；
- Cookie和密钥不会出现在Git、日志或普通业务表；
- 固定样本端到端测试通过。

## 19. 第二期扩展边界

第二期新增直播相关领域对象和模块，但不改变第一期核心边界：

- 直播录像作为新的内容来源适配器；
- 转写、章节和话术分析作为独立模块；
