# LiveDataShareAndThink 项目方向

更新日期：2026-07-09

## 1. 产品定位

LiveDataShareAndThink 是一个面向内容运营与直播增长的智能分析和内容生产平台。

平台先从小红书切入，通过公开内容、自有账号数据和人工提供的业务资料，发现热门趋势、拆解高表现内容、生成可审核的引流内容，并持续沉淀账号自己的运营知识。

项目不把“批量搬运”和“无人值守灌水”作为目标。核心价值是让选题和内容生产从主观猜测变成有数据依据、可追溯、可复盘的工作流。

## 2. 分期基调

### 第一期：内容引流

第一期只处理小红书内容运营，围绕以下闭环建设：

1. 设置赛道、品牌、账号定位、目标人群和关键词。
2. 获取相关公开笔记、账号、评论和互动指标。
3. 识别热点、内容机会、竞品模式和用户真实需求。
4. 拆解高表现内容的选题、标题、开头钩子、正文结构、视觉表达和互动设计。
5. 生成原创的直播预热、直播预约、直播后续承接等小红书内容。
6. 对生成结果执行事实、重复度、版权和平台规则检查。
7. 人工审核、修改、导出，后续再接入受控发布。
8. 回收发布后的表现数据，形成账号自己的内容经验库。

第一期的重点不是预测一个内容一定会爆，而是提高选题质量、内容生产效率和实验迭代速度。

### 第二期：直播复盘

第二期再引入直播录像、自有直播数据和业务结果，建设：

- 直播录制或录像导入；
- 语音转写和章节切分；
- 开场、留人、互动、异议处理和转化话术分析；
- 商品与核心卖点识别；
- 高光时段和短视频切片建议；
- 直播间表现与站外内容引流效果关联；
- 下一场直播脚本和改进建议。

## 3. 第一期明确不做

- 不做抖音、快手等多平台适配；
- 不做直播录像和直播话术复盘；
- 不承诺采集非公开的第三方成交、GMV或用户隐私数据；
- 不做规避验证码、风控或平台限制的对抗系统；
- 不默认无人审核直接发布；
- 不做简单洗稿、逐字仿写或未授权素材搬运；
- 不把某个非官方爬虫仓库直接改造成平台主体。

## 4. 产品原则

### 数据有来源

每个分析结论都应保留样本、时间范围、数据来源和计算依据，区分事实、模型推断和运营建议。

### 适配器可替换

小红书数据获取、模型供应商、图片生成和发布能力必须通过独立适配器接入。平台规则或第三方项目变化时，不应重写核心业务。

### 分析先于生成

生成内容必须引用选题依据、受众需求和已识别的内容模式，不能只依赖一段通用提示词。

### 原创而非复刻

系统可以抽象爆款结构，但不得复制原文、原图或独特表达。所有内容需保留参考来源和原创性检查结果。

### 人在回路

第一期生成结果先进入审核队列。发布、评论和其他可能影响账号的操作默认需要用户确认。

### 合规优先

优先使用官方开放平台、自有创作者后台导出和用户授权数据。非官方采集能力必须限频、可停用，并单独评估平台规则和许可证。

## 5. 第一期建议交付形态

第一期交付一个本地优先、可部署的 Web 工作台，至少包含：

- 研究项目与关键词管理；
- 数据采集任务和样本库；
- 热点与竞品分析；
- 爆款内容拆解；
- 评论需求和受众洞察；
- 数据驱动的选题池；
- 图文内容生成；
- 审核与版本管理；
- 内容资产和知识库；
- 基础效果复盘。

自动发布属于受控扩展能力，不是第一期最早里程碑的前置条件。

## 6. 开源复用策略

项目采用“研究现有实现、复用许可清晰的独立组件、自研核心领域模型”的方式：

- 许可宽松且边界清楚的项目，可以作为独立适配器或依赖；
- GPL 项目只在明确接受其许可证义务时集成；
- 非商业许可证项目只用于研究和原型验证；
- 未声明许可证的项目只学习产品思路和公开文档，不复制其代码；
- 平台的核心数据模型、评分方法、生成工作流和知识库由本项目自行实现。
